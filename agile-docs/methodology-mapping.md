# Methodology mapping

This document describes lightweight practices for this individual repository. It does not claim that ceremonies or organization-wide processes have been run.

| Practice | Applied here | Evidence / limitation |
| --- | --- | --- |
| Scrum | Prioritized backlog, sprint-sized goals, definition of done | Planning documents exist; no verified ceremony history is available. |
| Kanban | Backlog → Ready → In Progress → Code Review → Testing → Done; WIP limit 2 in progress, 2 review, 2 testing | Workflow policy is documented; no live GitHub Project board was found. |
| XP | Automated checks, small changes, review, tests around business rules | A limited test harness exists; tests were not passing/runnable at baseline. TDD and peer review are not evidenced. |
| Lean | Fix high-risk defects first; avoid duplicate tooling; record verified outcomes | No measured lead-time or cycle-time baseline exists, so no numeric improvement is claimed. |
| FDD | Track menu, order, bill, payment, reports, and table sessions as features | Existing app routes/pages provide feature boundaries; end-to-end acceptance is still needed. |
| Crystal-inspired | Lightweight written decisions and feedback notes | No team communication or retrospective ceremony is claimed. |
| DSDM | Use MoSCoW to prioritize scope | Prioritization is a planning aid only. |
| Adaptive development | Plan, collaborate, learn from verification and revise backlog | Iteration is recommended; no formal cycle history is evidenced. |
| Agile Unified Process | Inception, elaboration, construction, transition as a lightweight lifecycle | Mapping only; no full AUP implementation is claimed. |
